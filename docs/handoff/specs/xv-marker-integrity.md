# FINAL SPEC marker-integrity (ship=true)

## Summary
Ship. All four problems are real (Verified by reading origin/main 60bdfd97a; nothing edited, cargo not run). (1) daily_task_marker::write_marker_in returns unit and logs an uncoded warn! on failure, but crossverify run_once still logs "recorded" and returns Ok, so no retry happens and no page fires. (2) The write is std::fs::write in place, and the reader is is_file(), so a torn or zero-length marker reads as verified. (3) A batch flush in persist_report that fails mid-run calls discard_pending, yet persist_report returns !daily_failed. The day then counts as persisted and the marker releases the S3 hold with incomplete cell and tape tables. (4) A 7-day sweep deletes crossverify markers before the archive gate reads them (hot windows are 15 and 90 days), so verified days get the override path and log a false STORAGE-GAP-04. The fix: an atomic marker write that returns io::Result; a strict reader that checks content; a 400-day keep for crossverify markers; a failed marker write and any lost audit row each count as a failed attempt, retried and paged on the existing xverify_failed source. Review points folded in: an error after the rename is not a failure (Ok plus a coded warn); daily_archive gets an in-process latch, because a failed latch write would otherwise re-run up to 6 sweeps and then log a false 'did NOT complete' error; one shared marker-write helper so there is a single write site; no bare #[must_use] on io::Result (clippy::double_must_use under -D warnings); persist_report is split into a testable core; the rows counter stops over-counting; the §12.15.5 REJECT row is amended explicitly for the marker-only retry; the existing loss-group page for discarded rows is recorded. One review point is dropped: syncing every ancestor directory. A lost marker is the safe direction, so this is stated as a limit and not engineered.

Base: origin/main 60bdfd97a. Approval for the dated rows, quoted verbatim, 2026-10-06: "Go ahead with whatever you want dude" and "See do everything whatever is recommended dude okay?".

A. crates/app/src/daily_task_marker.rs
1. Core fn write_marker_in(base, task, date, keep_days) -> std::io::Result<()>. Run the body inside tickvault_storage::off_worker, as today.
   (a) Record whether `base` already exists, then call create_dir_all(base).
   (b) Open the fixed path <task>-<date>.marker.tmp with create, truncate and write, so a temp file left by a crash is overwritten. write_all the contents "build=<sha>\ndelivered_date_ist=<date>\n", then sync_all.
   (c) rename(tmp, final).
   Any error in steps (a) to (c) returns Err, and the marker is absent or old, which is the safe direction.
   (d) Directory sync: open `base` and sync_all it. If step (a) created `base`, also sync its parent. A failure here does NOT return Err, because the final file already exists and the strict reader will accept it. Log warn!(code = ErrorCode::StorageGap04S3ArchiveFailed? NO, use the caller-neutral path: the fn returns a WriteOutcome) — simpler, chosen: return Ok(DirSync::Failed(err)) or Ok(DirSync::Done). The type is `std::io::Result<MarkerDurability>`, where `enum MarkerDurability { Durable, RenamedNotDirSynced }`. Each caller logs RenamedNotDirSynced as a coded warn with its own code and treats the write as success.
   (e) The sweep runs after Ok. A sweep error is ignored, as today.
   Limit to state in the doc comment: only `base` and at most its parent are synced. A newly created grandparent (data/state) is not, so after a host crash the marker can be lost, which only re-runs or holds the day.
2. Strict reader. marker_exists_in reads the file through a reader capped at 4 KiB (Read::take). It returns true only if some line equals exactly `delivered_date_ist=<date>`. An empty, torn, wrong-date or unreadable file returns false. Markers already on disk use the same two-line format and still pass. The fail-open contract in the module doc is unchanged.
3. Sweep. Use keep_days in place of the constant. Also remove same-task `<task>-<date>.marker.tmp` files older than the cutoff. Foreign and unparsable names are still left alone.
4. Public API.
   - `try_write_daily_marker(task, date) -> io::Result<MarkerDurability>` uses DAILY_MARKER_SWEEP_DAYS (7).
   - `try_write_daily_marker_keeping(task, date, keep_days) -> io::Result<MarkerDurability>`.
   - Do NOT add a bare #[must_use]: io::Result already carries it, and clippy::double_must_use fails under -D warnings. If an attribute is wanted, it must be #[must_use = "..."] with a message, and even that is not needed.
   - Remove the unit-returning write_daily_marker so that no caller can silently drop the result.
   Update the module doc: atomic write, strict reader, per-task keep horizon.

Its doc must say it has to exceed the largest gated archive hot window (retention_days 90, market_data_hot_days 15, depth/intraday 1, after effective_hot_days) plus MAX_CROSSVERIFY_HOLD_DAYS (3). Add a const assert that 400 > 90 + 3. Add a boot check in spawn_dhan_live_crossverify, or in main.rs where the partition config is in scope: if max(gated effective hot days, retention_days) + MAX_CROSSVERIFY_HOLD_DAYS >= keep, emit ONE warn!(code = ErrorCode::WsGapConnectionState.code_str(), source = "xverify_marker_keep_short").

# FINAL SPEC 808 (ship=true)

## Summary
The defect is real and the fix should ship. On origin/main, `classify_disconnect` (crates/core/src/websocket/pool_supervisor.rs:757) puts 808 in the same Fatal arm as 806 and 810. That arm calls `park(ParkReason::FatalDisconnect)`, and `allows_one_respawn` is false for it, so a single 808 leaves the slot dark for the whole session. 807 and 809 refresh the token and redial instead (TokenStale arm, ~2950). Verified. The order side already handles 808 by refreshing and retrying once (oms/error_taxonomy.rs maps Data808 to TokenRefreshRetryOnce). Verified by review. connection.rs only decodes the code; the policy lives in pool_supervisor.rs alone.

This final spec keeps the design's shape: one shared, floored, jittered refresh-then-redial for a first 808, and a session park only after a fresh token is also rejected. 806 and 810 stay fatal on the first strike; 805 and ROTATION_HALTED are untouched. Review findings folded in:

(1) "Fresh" is now tied to WHICH token was verified. The token manager's `renew_generation` goes up on every token install (Verified at the acquire, renew, SSM-adopt and cache-adopt sites). The refresh closure already records the generation each dial presented (`dialled_generation`). So the slot parks only when the dial that got 808 presented the exact generation that an earlier refresh produced. This removes the stale `fresh_verified` problem across DialFailed loops, transient closes, 805 parks and probe releases, and later forced re-mints.

(2) A refusal because of the mint cooldown or RESILIENCE-03 is reported as `Deferred` and does not count toward the cap. A wall-clock limit on the whole episode (at least 2 × the 125 s mint cooldown) is the backstop. Without this, all 16 slots would park within about 20 s, while a mint would still have been refused for another ~100 s.

(3) A stacked `[data][808]` frame no longer clears the episode, because nothing on the frame path changes any more. The episode ends only when the credential has proven itself: a non-808 close after frames, or an 808 that arrives after at least MIN_HEALTHY_SESSION_MS of healthy delivery. So the first-frame edit, the hot-path edit and the DHAT concern are all gone.

(4) The 4-refreshes-per-session limit is replaced by a 4-per-300 s window, kept in a fixed `Copy` ring of timestamps.

(5) A failed renewal is now shared across sockets for 10 s. Before, coalescing only worked on success: 16 sockets with a dead token could each send their own failing RenewToken call. That also cuts the 807 path's auth-call burst.

(6) The freshness signal is the generation, not `expires_at`. The design wrongly assumed `expires_at` is the JWT exp (it is only on the SSM-adopt path), and the "re-adopts the same token from SSM" risk does not apply: the fallback is a fresh mint. Both points are dropped.

(7) The process blocker is fixed. origin/main already has exactly 5 active plans, the V7 cap, so the work goes into the existing IN_PROGRESS active-plan-feed-hardening.md rather than a 6th file.

(8) The missed guards and docs are added: the exact `ReconnectReason::ALL` label pin in `no_deliberate_redial_remains_for_a_subscription_change`, the two terraform alarm descriptions that say 808 parks permanently, AUTH-GAP-02 and the AuthGapDisconnectTokenMap doc, and the extra stale comments.

(9) For the depth account, an 808 refresh may only re-read its own SSM token, never call RenewToken or mint. A second token issuer for that account would break §10.4 and §10.9 of the minter rule.

(10) The noise-lock row now says honestly that a self-healing 808 can still fire the existing `dhan-main-reconnect-slow` alarm, exactly as 807 can.

Dropped as invalid or out of scope: the `From<()>` shortcut (it would let a production closure report a fresh token by default, a false OK); clearing the episode on the first frame (fails on stacked frames); using `Data808AuthFailed` as a new emit site (it could trip the code-coverage guards for no gain); and skipping renewal when sibling sockets are still delivering (no shared per-generation delivery signal exists, and 809 already renews on a single-socket rejection). That last one is recorded as a residual risk.

Hot path: no change per frame or per tick. Every new branch runs on the disconnect path or the refresh path, which are O(1), allocation-free and use `Copy` state.

ORDER IS BINDING. The rule files change first, then code, all in ONE PR. Branch off origin/main. Line numbers below are origin/main approximations; locate by SYMBOL.

# Following a tick from capture to the dashboard

**The November 25 daily check found a real discrepancy.** At 15:49 IST the Dhan process reported 67,905,584 accepted buffer writes. The database held 55,744,893 trades and quotes. The saved daily audit and the application log agree on a difference of 12,160,691 after three reads.

QuestDB deduplicates trade and quote rows using the timestamp, feed, segment, security ID and capture sequence. To identify an individual missing record, compare the keys of eligible captured market packets with the keys stored for the corresponding interval. ## Rechecking a corrupt mapping and a lost database reply

An archived margin mapping could assign two conflicting values to the same stock ID. The earlier reader accepted whichever JSON member came last. This could change the MTF selection when only the order of two fields changed. The normal typed writer produces unique keys. Repair commit `0ec2bcd79` makes disputed IDs unknown and keeps independent IDs and ordinary index memberships available. A late receipt from a newer source can also invalidate an unsupported historical interval. In a two-source model, the original reader returned 1,789 unsupported eligibility results across 59,040 cutoff checks. The repaired reader returned zero on those same checks. The single-source model retained its prior results across 59,040 checks.

| Check | Observation |
|---|---|
| Database accepted a write, then its response disappeared | In an isolated QuestDB, the writer queued the original 249-byte receipt. A second Rust process replayed those same bytes. The database held one row with all 11 fields before and after restarting, and a second drain found no pending journal. |
| Dashboard during a database restart | A single signed-in browser page showed the saved discrepancy, cleared both dated rows during the outage and restored them on recovery. Two daily rows survived four submissions. The protected API returned HTTP 401 to an anonymous request before and after. |
| Production Stocks portal at 19:13 IST, November 25 | Price Movers, F&O and Gainers were selected. The protected action returned `instance_stopped`, and the page explained the empty result. The running portal reported `9ccd99e` for the last binary, portal and main versions. |
| Meaning of the timing figures | The prior hosted same-day audit counter measured 31 ns p99 over 200,000 calls. Its slowest recorded call took 6.46 µs. A 100,000-row local database search measured 13.833 ms p99. Returning more rows requires more work. |
| Parsing the repaired published margin map | On this local machine, p99 for valid maps was 781 ns at eight IDs, 74,030 ns at 256 IDs, and 945,301 ns at 4,096 IDs (512 timed calls per case). At 4,096 IDs, the prior p99 was 703,783 ns. The receipt includes all five read paths and conflicting-key controls. |

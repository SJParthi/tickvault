Baseline: `/workspace/scratch/81296451ef3b/tickvault-audit`, commit `6637b52ec8d2604ba06b83b3f898f79aa7a85943`. Initial review was read-only; a later coordinator instruction authorized the scoped fixes listed below. Review date: 2026-09-14. No production access, load generation against a service, publication, or Cargo test run by this reviewer. Four isolated scanner probes were executed under `/tmp/tickvault-complexity-probe.Kppw2u`; results below. Prior 760-test evidence was not treated as a workspace proof.

## Decision

Strict worst-case O(1), zero allocations, runtime configurability, and constant memory everywhere are not properties this codebase has. Much of the per-instrument steady-state work is expected O(1), while full snapshots, history, ranking, parsing, replay, and serialization correctly scale with input/output. There are also concrete avoidable assurance and bounded-work gaps. Changing every container to Rust does not change these bounds.

Symbols used below: N = distinct instrument identities retained; A/D = instruments updated in a snapshot interval; R = ranked output rows; T = timeframe count (24 in this baseline); P = packets in a frame; L = depth levels; B = bytes read/serialized; Q = queued configuration updates; S = WAL segments. A hash lookup is expected/average O(1), not a proved worst-case constant bound. Allocator stalls, CAS retries, locks, scheduling and network latency are separate dimensions.

## 09:15 and retention envelope to measure before any capacity claim

1. Distinguish arrival rate, frame rate, packets per frame, levels per packet, distinct keys, new keys per second, traded keys per cadence, and output bytes. This source caps stacked walks at 70,000 packets and frame queues at 65,536 items plus byte limits; a frame-count test alone misses variable packet work.
2. Saturate the declared ceiling with valid new keys, while all four snapshot cadences coincide and all T=24 candle buckets need closure. Include equal-rank ties, all-gainer/all-loser populations, maximum depth packets, invalid bursts and delayed sequence replay.
3. Hold a downstream writer slow/unavailable within an explicitly finite interval. Record accepted frames, persisted raw ticks, folded/refused candles, retained/replayed bytes, dropped/refused rows, queue peaks, RSS and p50/p95/p99/max latency separately. No single counter proves the chain conserved data.
4. Replace subscriptions repeatedly while active count is constant; a cap on active keys is not a cap on identities ever visited. Include next-day reset without process restart.
5. Hold old Arc snapshots/read guards, exercise cache churn and overwrite paths, then release them. Memory may legitimately remain while readers retain versions; prove a reader-lifetime or backpressure bound before claiming constant resident memory.

No finite suite covers every permutation. It can establish a precisely stated envelope, improve confidence with shrinking/adversarial generators, and mechanically fail on regressions inside that envelope. Any all-input constant-time claim additionally needs algorithm/invariant reasoning and a defined computational model.

## Independent review of coordinator drain fairness changes

Source review found no definite dropped-frame or shutdown-hang defect in the new 64-frame quantum / maintenance bitmask design. Shutdown closes admission, retains accepted queued frames, and rejoins the common final-seal/flush path; production WalRingSink uses `try_send`, without held reserve permits. Work-item fairness does not establish a wall-clock deadline because individual frames and maintenance have variable work. Future callers holding channel permits indefinitely would need a separate shutdown contract.

The original new busy-drain regression depended on scheduler timing and allowed its second maintenance run after backlog exhaustion. Coordinator revised it to poll the pinned real drain before each of two virtual 61-second advances, count maintenance entries only while the receiver is nonempty, require at least two for each timer, and bound completion with a timeout. This tests timer dispatch under queued work, not snapshot contents, full output delivery, or a measured production latency envelope. The revised test remains uncompiled and unexecuted here.
